# SilkStack Image Browser v2.5.0

**v2.5.0 is the release where SilkStack starts answering a question your files never literally answer: what was this made with?** Every image now knows the architecture its checkpoint was built on — `SD 1.5`, `SDXL 1.0`, `Pony`, `Flux.1 D` — and you can sort by it, filter by it, search it, browse it as cards in the **Models** tab, and fill in the ones nothing knows about by hand.

It is also the release where a large library stops being slow to open. On a 20,000-image folder the first image now paints in **783 ms** instead of **11.8 seconds**, and the index finishes in **2.7 s** instead of **13.7 s** — because the file watcher was spending three of those seconds, and twenty thousand operating-system handles, watching files that never change. A library full of AI video no longer loads those videos into memory either, which is the difference between browsing it and crashing on it.

As always, everything AI runs **fully locally on your own GPU** — your images, prompts and tags stay on your machine. The only network calls the app makes are the documented ones: license activation and re-verification, model downloads on first use, update checks, the anonymous daily usage ping, and the base-model lookups described below, which send a **checkpoint's name or hash and nothing else**.

---

### Major Changes

**Every image now knows the base model behind it, and the whole library learns it at once.** The **Model** column has always shown the raw checkpoint name out of the generation metadata — `juggernautXL_v9Rundiffusion`, `ponyDiffusionV6XL_v6StartWithThis` — which identifies the file but tells you nothing about the architecture inside it, so "show me only my SDXL images" was not a question the library could answer. A new **Base Model** column answers it, in Civitai's own wording, sitting right after Model: it sorts like every other column, matches the search box, and appears in the sidebar as a **Base Models** facet whose last row is **Not resolved** — so the images nothing is known about are a bucket you can look at rather than an invisible remainder. The image viewer's sidebar shows the same line beside Model. **The lookup is per checkpoint, not per image**, which is the property the whole feature is built on: 18,000 images that came from 60 checkpoints is 60 lookups *once, ever*, not 18,000 — and once the table exists, re-resolving makes no requests at all. Each checkpoint is identified by a file hash when the metadata carries one (A1111's `Model hash:` is exactly Civitai's AutoV2), and by its normalized filename otherwise, which is also how a checkpoint resolved by hash goes on to answer for a ComfyUI image of the same file that has no hash. A near-miss is recorded as unknown rather than guessed at. Misses are cached too, so an old file Civitai has never heard of is not re-asked on every run. It is **on by default**, and its switch — with **Resolve now** and **Clear cached table** — is in **Settings → Base Models**, the screen that lists the checkpoints it is answering for; switching it off stops all of it and keeps the table you already have.

**Checkpoints the lookup cannot find can be mapped by hand — and the mapping covers every image of that model.** Civitai and Hugging Face know the checkpoints you still have on disk; delete a model file a year after generating a folder with it and those images are blank for good, with no way to say "that one was SDXL". **Settings → Base Models** is that way: one row per distinct checkpoint in your library, each with the image count behind it, unanswered ones sorted to the top, with a name filter and an **Only unmapped** switch for finding your row among sixty of them. The picker offers the same base-model list Civitai's own filter uses, grouped the way that filter groups them by publisher, with **Custom…** for anything it does not list. A hand-written answer is an ordinary row in the same table, which is what buys all of its behaviour at once: it is authoritative the moment it is written and never overwritten by a later lookup, it never ages out, it covers the hashed and the hash-less images of that model alike, and it is the one kind of row **Clear cached table** keeps. Nothing is re-indexed — the whole library updates the moment you save. A library whose checkpoints are all mapped resolves with **zero** network traffic, which is what the mapping is for.

**Base models are cards in the Models tab, not just a column.** The tab grouped by checkpoint, which answers *which model files do I have* and could not answer *which architectures do I have*. The architectures now stand on the same wall as their own cards, visibly their own kind, and clicking one filters the library to it exactly as clicking a checkpoint always has. The footer counts them apart — *N models · M base models* — and the wall follows the lookup as it resolves, so a checkpoint answered while the tab is open grows its card without a reload.

**A stack can be popped out into its own window.** A stack used to have exactly one place to be seen: drilled into, over the top of the library you were browsing. **Ctrl+click** (⌘+click on macOS) on a stack's blue badge, or on a stack card in the **Stacks** tab, opens it in a **window of its own** instead — so re-entering a stack you are already in no longer means leaving it. There is a right-click route too, **Open Stack in New Window**, which appears for any image that belongs to a stack. The new window is a **second view of the stack, not a navigation**: the drill-down behind it is left exactly as it was, so the same stack can be open in the main window and in its own window at once. It carries its own label, image count and title, remembers its own size and position, follows your theme, and closes with **Escape** — the same key that closes the viewer. It deliberately has no *Library* button or close **X**: both of those mean "go back to the grid behind me", and there is no grid behind this window. Opening an image from it opens the usual viewer, and a favourite set there is the favourite you see everywhere else.

**Hover a video — or an animated GIF — to preview it in place.** A card that can move no longer sits still: after a **200 ms** dwell the poster is replaced by a muted, looping preview, in the grid, in the list and in a stack's expanded view. Still images are a deliberate no-op and read no bytes at all. Hovering is a very frequent gesture, so the cost is managed centrally rather than per card: **one preview loads or plays at any moment**, a new hover supersedes the one before it however fast you move, a small cache makes re-hovering a card free, and a **mouse-down cancels immediately** — a press on a card is the start of a drag or of the click that opens the viewer, and neither wants a video playing behind it. Media that cannot be decoded leaves the poster on screen and stays quiet, because hovering is exploratory, not a request. There is an off switch — **Settings → General → Preview videos on hover**, on by default.

**Videos are streamed, not loaded — and a library full of them no longer eats your memory.** AI videos are routinely 50–500 MB, and a few large ones meant gigabytes of live buffers in the app, which is what a crash on first setup looks like from the inside. Video and image data now streams off disk through a privileged, range-serving protocol, so the player asks for what it needs and nothing more is buffered than what gets decoded; grid images, the viewer, thumbnails and the hover previews all use it. Videos no longer need the whole file *parsed* either — the MP4 metadata atom is read on its own, skipping the video data entirely — and the external probe is now a bounded fallback rather than a step every video goes through, with a timeout so a stubborn file cannot hang the queue. A hand-crafted URL pointing outside your library is refused, not served.

**Images appear while the folder is still being scanned.** The initial listing used to be one sequential stat per file, all of it returned in a single reply, so nothing could be shown until the last file in the tree had been read. The walk now streams, and the cached catalog **hydrates first** — so a folder you have opened before paints from cache before the scan has finished, and the scan then arrives as an incremental diff. Thumbnails are also no longer suppressed for the whole indexing window: they render **during** it, at a reduced budget so they cannot crowd out the work that matters, and a card that scrolls out of view cancels its own request instead of sitting in the queue. What that fixes is the wall of blank cards a large library used to be while it worked.

### Fixes

**Images no longer go missing from a stack view.** "Which images are in this stack?" was being answered by four different expressions in four places, and where they disagreed the views disagreed with them — a pair you had explicitly merged showed as two loose cards; a stack's identity was derived from its newest member, so a newer generation could close the drill-down you were looking at; an image that joined an open stack stayed invisible inside it. There is now **one rule** that every surface derives membership from, and a stack identified by a key that does not move when its membership does. An open stack stays open while images arrive and closes only when the group genuinely stops being one.

**A video that cannot be decoded no longer wedges every thumbnail after it.** The thumbnail pipeline waits for a video to report itself ready before it draws, and that wait had no timeout — so a corrupt or exotic file that never reported ready held its slot forever, and after eight of them **no thumbnail loaded again for the rest of the session**, in any folder. Every wait is now bounded, failures are remembered so scrolling back past a broken video retries nothing, and none of it surfaces an error: the poster stays and the app stays quiet.

**The base model now actually shows in the viewer.** "Base Model" was in Generation details for every image and visible for none — in the desktop build each click opens the viewer as a **separate window**, and a window is a separate process with its own copy of the lookup table. The main window resolved that table and read it; the viewer never read it at all, so the row never appeared, for any image, always. Every window that shows a base model now loads the table as it opens and is told when another window writes it, so two viewers open on the same library cannot disagree.

**A base model mapping now covers every image of that model, not just the ones without a hash.** Settings → Base Models states that a mapping applies to every image made with that checkpoint, and for half a library it did not: only the hash-less ones were answered from it, while the rest were looked up — and could then be overwritten by the looked-up answer. The rule is now the one the screen states: a mapping filed by name answers every image of that model and is consulted *before* the remembered answer, because correcting a checkpoint the lookup got wrong is the one thing that screen exists for.

**Filtering by a base model no longer hides the control that clears it.** Selecting a base model filter set the filter and unmounted the whole toolbar — sorting, the view toggles, and the **row of filter pills** that shows what is being filtered and lets you remove it. The one control that could have cleared the filter was inside the thing the filter had hidden. The toolbar's "is anything narrowing the grid?" test and the pills' own test were two hand-written copies of the same question; there is now one, both callers read it, and they cannot drift again.

**The dependency audit is down to the findings that have no patch to take.** `npm audit` reported **22** findings at the root, two of them critical; it now reports **15**, and neither critical is among them — both were one bug seen twice, a command-injection advisory reaching the build through a build-time tool, and both are gone. The remainder are all in build-time dependencies that are never packed into the shipped app, verified rather than assumed, and two of them **have no patched release to move to** — the newest published version of each is still inside its own advisory range, so only dropping the dependency could clear them. That trade is recorded rather than hidden.

### Minor Improvements

- **The viewer's sidebar is one card per group, and the star sits beside the file name.** An open group's header and body are one card rather than two tiles, the tag pills have a row of their own instead of sharing a line with the star, and the favourite star has moved out of the Tags group entirely — it belongs to the file, not to the file's tags, so favouriting no longer means expanding Tags first.
- **Renaming is a double-click on the file name.** The pencil button is gone: it sat in a wrapping row, so a long name pushed it onto a line of its own and the card grew a row that existed for some names and not others. The name now owns its row and the whole row is the target, whatever the name does.
- **Every icon-led readout names itself on hover.** A row that shows an icon rather than a label now carries its name across the whole row, not just over the 16-pixel glyph — "28" answers nothing until you know the row is about steps. Rows that already carry a text label get no tooltip, since repeating a label is just noise following the pointer. The help cursor is gone from everything that is not clickable.
- **Semantic search has exactly one switch, and it is in the search bar.** It used to have two, in two places, which disagreed in an ugly way: the sparkles in the search bar only appeared once the settings toggle had been switched on, so a feature switched off could not be switched back on from the bar. The settings card is removed, the sparkles are the feature's only control, and your stored preference is unchanged — so an install that had it on keeps it on and re-indexes nothing.
- **A new image joins its stack as soon as it is indexed, not after the models have run.** Grouping by prompt text is pure string comparison — no model, no GPU, no waiting — and it used to sit last in the pipeline round, behind the model phases. A freshly indexed image was correct but *ungrouped*, sitting as a loose card beside a stack it belonged to, for as long as the models took. It now runs second, immediately after stacking. The footer's phase counter follows.
- **Base-model lookups are paced.** The app's first outbound calls with any rate limiting at all: at most two at a time, spaced out, with a timeout, three attempts with backoff that respects a server's own "try again in N seconds", and an identifying user agent.

More features are coming soon. Follow, subscribe and keep looking for updates.
